1. 과제 개요

Open-Meteo, Countries.dev, ip-api의 JSON 데이터를 비동기로 동시에 수집했다. 수집 결과는 Pydantic v2 모델로 타입과 값의 범위를 검증하고, 검증을 통과한 데이터만 Pandas DataFrame으로 변환했다.

날씨·국가·IP 정보를 시간대별 하나의 표로 결합한 뒤 CSV와 Parquet으로 저장하고, 읽기·쓰기 시간과 파일 크기를 비교했다. 저장 형식의 차이를 데이터 크기별로 확인하기 위해 100행부터 100만 행까지 합성 매출 데이터 벤치마크도 수행했다.

비동기 수집

asyncio.gather()와 httpx.AsyncClient를 사용해 날씨·국가·IP API를 동시에 호출했다.

스키마 검증

Pydantic v2 모델로 자료형, 필수 값, 기온·강수확률·위경도 범위를 검증했다.

저장 성능 비교

동일한 데이터를 CSV와 Parquet으로 저장하고 읽기·쓰기 시간과 파일 크기를 측정했다.

코드 품질

pytest로 정상·오류·저장 흐름을 테스트하고 Ruff로 코드 품질을 확인했다.

3. 코드 분석

3.1 비동기 API 수집

  • httpx.AsyncClient 하나를 생성해 날씨·국가·IP 요청에서 재사용했다.
  • asyncio.gather()로 세 코루틴을 함께 스케줄링해 동시에 요청했다.
  • raise_for_status()로 HTTP 오류를 확인하고, 429·5xx 오류는 최대 3회 재시도했다.
  • 과제에서 지정한 http://ip-api.com/json/8.8.8.8 주소를 사용했다.

3.2 Pydantic v2 검증

  • 기온은 -100~60℃, 강수확률은 0~100 범위로 제한했다.
  • 위도는 -90~90, 경도는 -180~180 범위로 제한했다.
  • 날씨의 시간·기온·강수확률 배열 길이가 같은지와 빈 배열 여부를 확인했다.
  • 국가명·수도·지역은 빈 문자열을 허용하지 않고 인구는 양수만 허용했다.
  • IP 응답의 status가 success인지 먼저 확인했다.

3.3 DataFrame 변환

  • 날씨는 시간대별 한 행으로 변환하고 Pydantic의 datetime 검증을 적용했다.
  • 국가와 IP 정보는 각 날씨 행에 결합하여 하나의 분석용 DataFrame으로 구성했다.
  • 저장 전 모든 값이 검증된 모델에서 나온 데이터인지 보장했다.
설계 판단: 현재 구현은 한 API가 최종 실패하면 전체 저장을 중단하는 fail-fast 방식이다. 부분 성공 결과를 저장해야 한다면 return_exceptions=True와 API별 오류 처리를 추가할 수 있다.

4. 저장 및 프로그램 실행 결과

4.1 저장과 성능 측정

  • CSV와 Parquet 모두 index=False로 저장했다.
  • Parquet은 Pandas가 설치된 PyArrow 엔진을 사용해 저장했다.
  • time.perf_counter()로 읽기·쓰기 시간을 각각 측정했다.
  • 저장한 파일을 다시 읽고 원본과 행·열 개수가 다르면 예외를 발생시켰다.
  • 벤치마크 임시 파일은 크기를 기록한 직후 삭제해 결과 폴더를 정리했다.

7. 본인 의견 및 개선 사항

실습을 통해 확인한 점

  • 비동기 처리는 함수에 async를 붙이는 것만으로 끝나는 것이 아니라, 여러 코루틴을 asyncio.gather()로 함께 스케줄링해야 동시 요청의 효과를 얻을 수 있었다.
  • HTTP 요청이 성공해도 값의 범위나 배열 길이가 잘못될 수 있으므로 저장 전에 Pydantic 검증이 필요하다고 판단했다.
  • CSV와 Parquet 중 한 형식이 항상 우수한 것은 아니었다. 작은 데이터에서는 CSV가 단순하고 효율적이지만, 데이터가 커질수록 Parquet의 압축과 읽기 성능이 유리했다.
  • 성능 결과는 행 수, 열 구성, 자료형과 실행 환경을 함께 고려해 해석해야 한다.

추가 개선 사항

  • 행·열 개수뿐 아니라 dtype과 주요 값까지 비교하는 저장 무결성 검사를 추가한다.
  • 벤치마크를 여러 번 반복해 평균과 표준편차를 계산하고 압축 방식별 결과를 비교한다.
  • 데이터가 커질 경우 날짜별 Parquet 파티셔닝을 적용한다.
  • 출력 경로, timeout, 반복 횟수를 명령행 옵션으로 선택할 수 있도록 개선한다.
  • 부분 API 실패 허용 여부를 설정으로 분리하고 마지막 정상 데이터 캐시를 활용한다.
